# 前端 UI 设计书

## 1. 概述

本文档定义工业管理 APP 各页面的 UI 布局、组件结构、配色方案与交互规范。

**设计基准**：原型站点 demo.niubi748.top 逐页还原
**目标分辨率**：393 × 852（手机竖屏）
**设计原则**：信息密度适中、工业风格简洁、状态颜色语义明确
**关联文档**：[前端Harmony设计书](../../设计书/前端Harmony设计书.md)、[前端接口设计](../../接口设计/前端接口设计.md)

## 4. 页面设计

### 4.1 登录页（Login）

```
┌─────────────────────────────────────┐
│                                     │
│         [工厂图标]                   │
│                                     │
│      工业管理 APP                    │
│    柔性组装 MES 仿真系统             │
│                                     │
│   ┌─────────────────────────────┐   │
│   │ 请输入账号                   │   │
│   └─────────────────────────────┘   │
│   ┌─────────────────────────────┐   │
│   │ 请输入密码           [👁]    │   │
│   └─────────────────────────────┘   │
│                                     │
│   ┌─────────────────────────────┐   │
│   │          登 录               │   │
│   └─────────────────────────────┘   │
│                                     │
└─────────────────────────────────────┘
```

- 页面背景：#f5f5f5
- 图标：80×80px，主色
- 输入框高度：48px
- 登录按钮：全宽，48px 高，主色背景

#### 功能设计
- 账号密码输入与校验（非空校验）
- 密码输入框支持显示/隐藏切换
- 点击登录调用 `AuthApi.login`，成功后存储 token 和角色
- 登录成功按角色分流：班组长 → LeaderHome，操作员 → OperatorHome，质检员 → InspectorHome，管理员 → AdminHome
- 网络错误时 Toast 提示"网络连接失败"

#### 角色权限
- 所有角色共用同一登录页
- 登录表单无角色选择，由后端返回角色决定首页

## 6. 按钮 UX 设计

### 6.1 按钮状态机

所有业务操作按钮统一遵循以下状态流转：

```
正常(可点击) → 按下(颜色加深) → 加载中(转圈动画) → 成功/失败(图标1.5s) → 恢复正常
```

- **正常**：主色背景，白色文字，可点击
- **按下**：背景色加深 10%，提供触觉反馈
- **加载中**：显示 Loading 动画，禁用点击，防止重复提交
- **成功/失败**：显示结果图标 1.5s 后自动恢复为正常态
- 危险操作（报废、删除）额外增加二次确认弹窗

### 6.2 权限矩阵对按钮的影响总表

| 页面 | 按钮 | 可见角色 | 禁用条件 | 无权限时表现 |
|------|------|---------|---------|-------------|
| WorkOrderList | [+] 新增 | admin, leader | - | 隐藏 |
| WorkOrderList | 编辑 | admin, leader | status ≠ '待派工' | 置灰 |
| WorkOrderList | 复制 | admin, leader | - | 隐藏 |
| PendingDetail | 确认派工 | admin, leader | status ≠ '待派工' | 置灰 |
| PendingDetail | 编辑 | admin, leader | status ≠ '待派工' | 置灰 |
| AssignedDetail | 开始生产 | admin, operator | 非当前操作员 | 隐藏 |
| RunningDetail | 暂停 | admin, operator, leader | - | - |
| CompletedDetail | 报工 | admin, operator | status ≠ '生产完成' | 置灰 |
| PausedDetail | 恢复生产 | admin, operator, leader | - | - |
| PausedDetail | 报废 | admin, leader | status 不在 {暂停中, 已报工} | 置灰 |
| ReportedDetail | 确认完工 | admin, leader | 无抽检记录 | 置灰 |
| ReportedDetail | 报废 | admin, leader | status 不在 {暂停中, 已报工} | 置灰 |
| LineDetail | 启动整线 | admin, operator, leader | 产线非空闲 | 置灰 |

- 权限校验优先级：角色可见性 > 状态禁用条件

### 6.3 危险操作 UX

涉及数据不可逆变更的操作称为危险操作，必须触发二次确认：

| 操作 | 弹窗标题 | 提示文案 | 确认按钮文案 | 确认按钮颜色 |
|------|---------|---------|-------------|-------------|
| 报废工单 | 确认报废？ | 报废后工单将不可恢复，是否继续？ | 确认报废 | #f5222d |
| 删除人员 | 确认删除？ | 删除后该账号将不可用，是否继续？ | 确认删除 | #f5222d |
| 停止整线 | 确认停止？ | 停止后当前工单将标记为生产完成，是否继续？ | 确认停止 | #faad14 |
| 复位整线 | 确认复位？ | 复位将清空所有计数器，是否继续？ | 确认复位 | #faad14 |
| 退出登录 | 确认退出？ | 退出后将清除本地登录状态，是否继续？ | 确认退出 | #333333 |

- 弹窗布局：标题居中 + 提示文案居中 + 底部左右按钮（取消在左，确认在右）
- 取消按钮：灰色边框，白色背景，黑色文字
- 确认按钮：根据危险程度使用红色（不可逆）或黄色（可逆但影响大）

### 6.4 乐观 UI 设计

对于产线操作（启动/停止/复位）和工单状态变更（派工/开工/报工/确认），采用乐观 UI 策略：

1. **用户点击按钮后立即响应**：
   - 按钮置灰并显示加载动画
   - 本地预更新状态（如产线状态从"空闲"变为"运行中"）

2. **等待服务端广播确认**：
   - 通过 WebSocket 接收状态变更广播
   - 若广播内容与本地一致，保持当前 UI
   - 若广播内容不一致（如操作被拒绝），回滚本地状态并提示错误

3. **超时兜底**：
   - 3 秒内未收到 WebSocket 广播，自动调用 REST API 拉取全量状态
   - 若 API 返回失败，回滚本地状态并显示 Toast 错误提示

4. **并发冲突处理**：
   - 乐观锁版本冲突（HTTP 409）时，弹窗提示"数据已被修改，请刷新后重试"
   - 自动触发页面全量刷新

```arkts
// 示例：乐观 UI 按钮状态管理
@Trace isLoading: boolean = false
@Trace localStatus: string = '空闲'

handleStart() {
  this.isLoading = true
  this.localStatus = '运行中' // 乐观更新

  LineApi.start(this.lineId)
    .catch(() => {
      this.localStatus = '空闲' // 回滚
      promptAction.showToast({ message: '启动失败' })
    })
    .finally(() => {
      this.isLoading = false
    })

  // WebSocket 广播到达时再次校验
  // 若 broadcast.status !== localStatus 则回滚
}
```
