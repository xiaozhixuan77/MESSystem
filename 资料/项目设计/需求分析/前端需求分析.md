# 前端需求分析

## 1. 项目概述

工业管理 APP（柔性组装 MES 教学/仿真版）是一款面向制造业执行系统的移动端应用，基于 HarmonyOS 平台开发，目标分辨率为 393×852（手机竖屏）。应用采用 ArkTS + ArkUI V2 技术栈实现。

**目标读者**：鸿蒙端开发者
**关联文档**：[后端需求分析](后端需求分析.md)、[前端Harmony设计书](../设计书/前端Harmony设计书.md)、[前端接口设计](../接口设计/前端接口设计.md)、[HarmonyOS ArkTS 架构学习记录](../../../../ObsidianKu/Claude知识库/技术栈/前端/HarmonyOS ArkTS 架构学习记录.md)

## 2. 核心需求

### 2.1 平台与设备
- **目标平台**：HarmonyOS（API 12+）
- **目标设备**：手机（Phone）为主，预留平板/折叠屏扩展
- **屏幕方向**：竖屏（Portrait）
- **目标分辨率**：393 × 852
- **SDK 版本**：HarmonyOS SDK 6.0.2 (API 22)

### 2.2 技术架构约束

参考知识库 [HarmonyOS ArkTS 架构学习记录](../../../../ObsidianKu/Claude知识库/技术栈/前端/HarmonyOS ArkTS 架构学习记录.md) 的工程规范：

| 维度 | 规范 |
|------|------|
| 架构模式 | MVVM（Model-View-ViewModel） |
| 状态管理 | ArkUI V2（`@Local` / `@Param` / `@Event` / `@Trace` / `@ObservedV2`） |
| 导航路由 | Navigation + NavPathStack（禁用旧版 `@ohos/router`） |
| 模块架构 | common → features → products 分层 HAR/HSP |
| 断点适配 | sm（手机）/ md（平板竖屏）/ lg（折叠屏横屏） |

### 2.3 多角色支持
系统包含四个角色，同一套页面按角色过滤权限和可见区域：

| 角色 | 核心权限特征 |
|------|-------------|
| 班组长 (Leader) | 维护本班组工单、派工、确认工时、异常处理、只读查看产线和看板 |
| 操作员 (Operator) | 执行被派工单、扫SN开工、启动整线、报工 |
| 质检员 (Inspector) | 抽检录入、只读看产线运行、质检看板 |
| 管理员 (Admin) | 全权限：人员管理、产线/工艺维护、全局工单总览 |

### 2.4 底部导航
全应用统一底部 4 个 Tab：
1. **工作台** — 角色化首页，展示待办与快捷入口
2. **数据** — 产线列表、产线详情、工作站详情
3. **工单** — 工单列表及详情变体
4. **我的** — 个人账号信息

### 2.5 核心功能模块

#### 2.5.1 登录模块
- 账号密码登录
- 登录后根据角色进入对应工作台
- JWT Token 通过 Preferences 持久化存储
- 使用 `replacePath` 跳转首页（避免导航栈累积）

#### 2.5.2 工作台模块
- **班组长**：快捷入口（基础数据/工单/质检看板）+ 待派工/异常待处理待办卡
- **操作员**："我的待办" — 只展示自己关联的工单
- **质检员**：待办卡（产线运行状态/待抽检工单/故障日志待核查）
- **管理员**：4 个 KPI 卡（产线总数/人员总数/活跃工单/待处理异常）

#### 2.5.3 工单模块
工单状态机驱动页面变体：
- 工单列表（按角色过滤）
- 新增/修改/复制工单
- 待派工详情 / 派工
- 已派工查看
- 生产中查看
- 生产完成详情（业务别名"待报工"，非独立状态值）
- 已报工 / 确认工时
- 暂停 / 恢复 / 报废

#### 2.5.4 生产执行模块
- 生产任务列表（待执行/进行中/已报工）
- SN 扫码开工
- 产线详情（整线状态 + 7 个工作站）
- 工作站详情（设备/工作/传送带状态、计数器）
- 整线启动/停止/复位/异常上报

#### 2.5.5 质检模块
- 待抽检工单列表
- 抽检详情 / 录入结果
- 质检看板（Dashboard）

#### 2.5.6 管理模块（管理员独有）
- 人员管理（增删改查，按角色 Tab 切换）
- 产线与工艺管理（只读展示，通过产线详情页 LineDetailPage 查看关联工艺列表）
- 全产线工单总览

### 2.6 实时状态同步

**业务需求**：多角色实时协同，操作员在窗口 A 对产线做任何操作，班组长/质检员/管理员的窗口 B 在 2 秒内自动同步刷新。

**技术方案**：
- WebSocket（@ohos.net.webSocket）
- 封装全局 WebSocketService 单例（`@ObservedV2`，可追踪连接状态）
- 页面级订阅管理（进入 `aboutToAppear` SUBSCRIBE，离开 `aboutToDisappear` UNSUBSCRIBE）
- 断线重连机制（心跳 30 秒，超时 60 秒重连）
- 乐观 UI（先置灰按钮，等服务端广播确认）
- 断网恢复后先拉全量 REST，再接收增量推送

### 2.7 扫码功能
- 操作员扫码 SN（序列号）开工
- 建议预留扫码弹 SOP（标准作业指导书）能力

### 2.8 图表展示
- 质检看板 KPI 指标
- 本月计划达成率趋势柱状图
- 使用 @ohos/mpchart 库

## 3. 非功能性需求

### 3.1 性能
- 页面切换流畅，无卡顿
- 产线状态刷新延迟 < 2 秒
- WebSocket 断网 30 秒后恢复能自动重连并拉全量
- 列表使用 `LazyForEach` 虚拟滚动
- 10 产线并行仿真时 APP 端渲染不卡顿

### 3.2 安全
- JWT Token 安全存储（Preferences）
- 密码输入框脱敏
- 接口请求统一鉴权（Header Bearer Token）

### 3.3 兼容性
- HarmonyOS 5.0+ 手机设备
- 适配不同屏幕密度
- 预留 md/lg 断点布局扩展

### 3.4 可用性
- 操作按钮置灰提示（无权限时）
- 异常状态红色高亮
- 空状态友好提示

## 4. 约束与假设

- 一个操作员同一时间只能 "激活" 一个工单
- 产线仿真数据由后端 Scheduler 驱动，前端仅接收和展示
- 二维码扫描能力由设备硬件提供，前端调用系统 API
- 原型用 localStorage 模拟实时同步，真实开发替换为 WebSocket，业务语义保持一致
- **前端架构严格采用 V2 装饰器**，禁止 V1/V2 混用
- **导航统一使用 Navigation + NavPathStack**，禁用旧版 @ohos/router
- **工程采用 common → features → products 分层**，符合多端部署规范
