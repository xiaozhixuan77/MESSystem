# 前后端合并测试设计书

## 1. 概述

本文档定义工业管理 APP 前后端联调测试方案，重点关注实时状态同步、多角色协同、端到端业务闭环的验证。

**测试范围**：前端 HarmonyOS APP + 后端 Spring Boot 全链路
**测试重点**：WebSocket 实时同步、多角色并发操作、工单状态机流转
**关联文档**：[前端测试设计书](前端测试设计书.md)、[后端测试设计书](后端测试设计书.md)、[后端需求分析](../需求分析/后端需求分析.md)

## 3. 端到端业务闭环测试

### 3.1 核心业务流程 E2E-001

| 3 | 班组长 | 点击派工，选择操作员 | 显示派工成功 Toast | 数据库 status=已派工 |
| 4 | 操作员 | 登录设备 B | 工作台显示 "去生产" 待办 | - |
| 5 | 操作员 | 点击 "去生产" | 进入工单详情，显示 "开始生产" | - |
| 6 | 操作员 | 点击开始生产 | 状态变为 "生产中" | 数据库 status=生产中，仿真启动 |
| 7 | 班组长 | 查看产线详情 | 看到产线状态 "生产中"，工作站计数递增 | WebSocket 推送正常 |
| 8 | 操作员 | 点击停止 | 状态变为 "暂停中" | 数据库 status=暂停中 |
| 9 | 班组长 | 查看产线详情 | 状态同步为 "暂停中" | WebSocket 广播延迟 < 2s |
| 10 | 操作员 | 点击恢复 | 状态恢复 "生产中" | 仿真恢复 |
| 11 | 操作员 | 点击停止或等待仿真器完成 100 件计数 | 状态自动变为 "生产完成" | - |

| 13 | 质检员 | 登录设备 C | 工作台显示 "待抽检" | - |

**验收标准**：全部步骤通过，数据一致性 100%

### 3.2 异常处理流程 E2E-002

**场景**：产线异常上报与处理

## 4. 实时状态同步测试

### 4.1 产线状态同步 SNC-001

**目标**：验证操作员操作后，班组长端实时同步

```
设备 A（班组长）          服务端              设备 B（操作员）
     │                      │                      │
     │                      │ ◄── 点击 "启动整线" ───│
     │                      │                      │
     │                      │ 启动仿真任务          │
     │                      │ status: 空闲→生产中   │
     │                      │                      │
     │ ◄── 广播 /topic/lines/1 ───────────────────│
     │ 产线状态: 生产中      │                      │
     │ （延迟 < 2s）        │                      │
     │                      │                      │
     │                      │ ◄── 每秒 tick ────────│
     │                      │ 推送工作站计数        │
     │                      │                      │
     │ ◄── /topic/lines/1/stations ───────────────│
     │ rawCount=1 finishedCount=0                │                      │
     │                      │                      │
```

**测试步骤**：
1. 设备 A 打开产线详情页（柔性组装线）
2. 设备 B 打开同一产线详情页
3. 设备 B 点击 "启动整线"
4. 记录设备 A 状态变化时间
5. 验收标准：设备 A 在 2 秒内显示 "生产中"

## 6. MySQL 优化端到端验证

### 6.1 production_log 分区管理验证 DBV-001

**目标**：验证分区表在实际运行中的正确性

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 启动产线仿真，运行 30 分钟产生大量 production_log | 数据按 event_time 写入对应月份分区 |
| 2 | 执行 `SELECT PARTITION_NAME, TABLE_ROWS FROM information_schema.partitions WHERE table_name='production_log'` | 当前月份分区有数据，其他分区数据正确 |
| 3 | 执行分区归档脚本（将 3 个月前分区移动到 production_log_archive） | 归档表有数据，原表对应分区数据已迁移 |
| 4 | 查询归档表数据 | 数据完整性 100%，无丢失 |
| 5 | 添加未来月份分区（如 p202601） | `ALTER TABLE` 成功，新分区可见 |

### 6.2 Redis 缓存一致性验证 CAC-001

**目标**：验证 Redis 缓存与 MySQL 的最终一致性

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 启动产线，观察 Redis `mes:station:1` | Hash 字段实时更新（raw_count, finished_count） |
| 2 | 停止产线，等待 10 秒 | MySQL workstation 表数据与 Redis 一致 |
| 3 | 直接查询 MySQL `SELECT * FROM workstation WHERE id=1` | `raw_count` 等于 Redis 中的值 |
| 4 | 停止 Redis 容器，刷新前端产线详情页 | 前端从 MySQL 读取并正确显示状态 |
| 5 | 重启 Redis，执行预加载脚本 | `mes:station:*` 全部恢复，数据正确 |

### 6.3 复合索引查询性能验证 IDX-001

**目标**：验证 `idx_status_created_at` 在实际查询中的效果

| 步骤 | 操作 | 预期 |
|------|------|------|
| 1 | 班组长工作台加载"待派工"工单列表 | 查询时间 < 200ms |
| 2 | 后端开启慢查询日志 | 无 `work_order` 表全表扫描记录 |
| 3 | `EXPLAIN` 分析班组长工作台查询 SQL | `key` 字段显示 `idx_status_created_at`，`Extra` 无 `Using filesort` |

## 10. 缺陷等级定义

| 等级 | 定义 | 示例 |
|------|------|------|
| P0（致命） | 系统崩溃、数据丢失、安全漏洞 | 状态机并发导致数据错乱 |
| P1（严重） | 核心功能不可用、阻塞流程 | WebSocket 完全断开无法重连 |
| P2（一般） | 功能可用但体验差 | 同步延迟 3~5 秒 |
| P3（轻微） | UI 问题、文案错误 | 状态标签颜色不对 |

| 分区管理 | production_log 按月分区，归档数据完整无丢失 |
| 复合索引效果 | 班组长工作台查询 < 200ms，无全表扫描 |
