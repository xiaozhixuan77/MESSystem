# 		项目实施计划书

## 1. 项目概述

**项目名称**：工业管理 APP（柔性组装 MES 教学/仿真版）
**项目周期**：约 10 ~ 13 周（单人全栈）/ 约 6 ~ 8 周（前后端各一人并行）
**关联文档**：[前端需求分析](需求分析/前端需求分析.md)、[后端需求分析](需求分析/后端需求分析.md)、[前端Harmony设计书](设计书/前端Harmony设计书.md)、[后端SpringBoot设计书](设计书/后端SpringBoot设计书.md)

## 2. 技术栈确认

| 端 | 技术栈 | 版本 |
|:---|:---|:---|
| 前端 | HarmonyOS + ArkTS + ArkUI V2 | **API 22（SDK 6.0.2(22)）** |
| 后端 | Spring Boot + MyBatis-Plus + MySQL + Redis + WebSocket(STOMP) | JDK 17 |

| 构建 | Maven（后端）/ Hvigor + OHPM（前端） | - |

## 3. Git 管理规范

### 3.1 分支策略（Git Flow 简化版）

```
main          ──────────────────────────────────────────
               │            │            │
release/v1.0  ─┴────────────┘            │
               │                         │
develop       ─┴─────────────────────────┘
               │
feature/xxx   ─┴─ ─┴─ ─┴─ （每个功能分支）
```

| 分支 | 用途 | 保护策略 |
|------|------|---------|
| `main` | 生产就绪代码，仅接受 release 合并 | 禁止直接推送 |
| `develop` | 日常开发主分支 | 禁止直接推送，需 PR |
| `feature/*` | 单个功能开发 | 从 develop 切出，完成后合并回 develop |
| `release/*` | 版本发布准备 | 从 develop 切出，完成后合并到 main 和 develop |
| `hotfix/*` | 生产紧急修复 | 从 main 切出，完成后合并到 main 和 develop |

### 3.2 提交信息规范

必须使用 [提交模板](git-commit-template.md)，格式：

```
<type>(<scope>): <subject>

<body>

<footer>
```

**Type 必须**：
- `feat`：新功能
- `fix`：修复
- `docs`：文档
- `style`：格式（不影响代码运行的变动）
- `refactor`：重构
- `test`：测试
- `chore`：构建过程或辅助工具的变动
- `docker`：Docker 相关

### 3.3 提交原则

- **原子提交**：一次提交只做一件事
- **频繁提交**：每完成一个可编译/可运行的最小单元即提交
- **提交即可用**：每次提交后代码应能编译通过
- **关联 Issue**：如有 Issue 追踪，提交信息中引用 `#123`

## 6. 风险管理

| 风险 | 影响 | 应对措施 |
|------|------|---------|
| WebSocket 延迟不达标 | M3 延迟 | 预留 1 周缓冲，必要时降级为 SSE + 轮询兜底 |
| 鸿蒙模拟器调试困难 | M3/M4 | 尽早申请真机调试资源 |
| 产线仿真 CPU 过高 | M3 性能 | 使用线程池 + 异步处理，可接受降频到 0.5Hz |
| 数据库性能瓶颈 | M5 性能 | 预留 Redis 缓存层，production_log 按表分区 |
